# 证据与评分

## 口径与证据账本

- 先做型号身份表。每家主榜只取一款满足本次公开可用口径的旗舰，独立列可用的旧版和便宜型号。型号、推理档位、日期、平台、工具权限和版本不一致时做标记。应用宣称已上架与普通账号实际可选也可能不同。
- 用中文和海外来源分别搜索，再按证据类型交叉补缺。榜单优先原始发布者和具体子榜。独立实测优先作者原文、同题、原始输出、失败样例、重复次数及实际账单。论坛评论用于修正延迟、额度、区域/入口、返工和持久使用体验。转发、镜像或同一作者的图文和视频按一份证据计。
- 看视频正文、字幕、时间戳、配套提示词与成品。只有标题、封面或无法核对的转述时只记线索。厂商自测标为厂商来源，评估提供商自己的产品、商业软文或有工具绑定时标明。不要把测试集分数、输出偏好和个案故障当成同一指标。
- 逐条记下日期、模型/强度、同题条件、任务与样本、关键数字或成功失败、判分者、付费或赞助关系（能确认时）、原始链接。标明用这条证据支持哪个模型及维度。比较跨站结论前先检查任务范围和版本。对强结论争取找到彼此独立的证据，优先补会改变推荐的空白，避免凑数量。
- 每个维度给出最能改变结论的证据。遇到互相矛盾的结果，说明是任务类型、外层工具、模型档位、评分口径还是地区造成差别。小样本只支持具体任务级结论。对范围内缺数据的型号明确写出缺口，继续完成其余内容。

## 把证据映射到能力

| 维度 | 优先观察 |
| --- | --- |
| 科学推理 | 新题、多步推导、推理校验、科学数据分析。区分闭卷推导、用工具的科研智能体和答对率 |
| 编程 | 仓库内修复、测试通过、前端成品、指令遵循、返工。分别看从零造、已有工程、网页和原生软件 |
| 事实可靠性 | 答对、答错、拒答、假引用、资料覆盖。分开记录闭卷事实与联网来源，人工打开来源确认是否支持结论 |
| 智能体办公 | 可编辑 PPTX/DOCX、保留版式、任务闭环、跨文件检索、执行后校验。记录模型和外层工具，观察交付而非口头声明 |
| 文学与对话 | 角色和文气、语言自然度、约束与人物一致性、多轮语气稳定、主动澄清与啰嗦程度。默认文学约 60%、对话约 40%，中文和外文作品应尽可能分开检查 |

默认来源类型为榜单、独立作者实测、用户经验，目标权重约 25/60/15。中文与海外来源默认约 60/40，交叉目标为中文 15/36/9，海外 10/24/6。来源语言或社群用实际发布平台与受众判断，不按模型国籍判断。官方版本和计费事实单独核对。来源覆盖通常不均，权重可用于编辑判断，报告须写明实际限制；只有具备同口径分组评分时才声称精确计算了权重。不要用空白组补分或凭空造出六格分值。

建议按同一标尺比较。95–100 代表多类任务有直接头部证据，90–94.9 代表整体强而场景明显分化，85–89.9 代表常见任务胜任而复杂任务更依赖条件，80–84.9 代表强弱较分明，其余分数按证据下调。证据强度和能力水平分开记录。同一条证据支持暂定分不宜伪装成精确测量。相近分数标明属于同一梯队或不确定先后。允许等分，合计按各维度的一位小数计算。用户要求不同维度、尺度或计分方式时优先按用户口径。

## 场景与成本

先过滤用户不能用的供应商、地区、入口和工具。场景推荐要明确模型、App 或客户端、套餐/按量，以及普通操作与难任务是否切换。按已包含的额度、现金成本、等待和返工比较，不把总榜机械套进每个场景。

对可比 API 报价用统一输入量、输出量、缓存假设和币种，标明汇率日期、地区、峰谷价、长上下文和折扣截止。默认示例是 10 万输入、2 万输出、无命中，金额 = 输入单价 × 0.10 + 输出单价 × 0.02。区分模型费、工具费、已订阅额度和额外订阅费，允许按量未知或额度不可横向比较。实际任务账单注明样本和思考开销。
